## 整体实现思路

### 1. 程序输入与输出

- **压缩时**
  - **输入**：一张普通的 `.png` 图片（纯色图、渐变图、风景图）。
  - **输出**：自定义文本文件，后缀为 `.okti`。
- **解压时**
  - **输入**：一个 `.okti` 文件。
  - **输出**：还原得到的 `.png` 图片。

`.okti` 是纯文本，按行存放指令，格式约定如下：

1. 第一行必须是小写标识 `okti`。
2. 第二行是十进制宽高，中间一个空格，例如 `256 256`。
3. 之后每一行是一条指令：
   - `n` + 十六进制正整数：接下来这个颜色连续重复多少个像素，例如 `n9C4` 表示 2500 次。
   - `p` + 6 位十六进制 RGB：颜色本身，例如 `pFF0000` 是红色。
4. 某一段颜色只出现 1 次时，编码器省略 `n`，解码器默认重复次数为 1。
5. 读取时会跳过空行。像素按从左到右、从上到下的顺序展开。

### 2. 核心处理步骤

**第一步：读取图片**

用 Python 图像库（PIL）打开图片，转成 RGB，取出宽高，再按行优先把像素读成列表。每个像素是 `(R, G, B)` 三个 0–255 的整数。带透明通道的 PNG 会丢掉 alpha，只保留颜色。

**第二步：压缩图片（游程编码 RLE）**

大片同色区域不必把颜色写几百次。

- 从头到尾扫描像素。
- 当前像素和上一个颜色相同，计数器加 1。
- 颜色发生变化时，把上一段写进文件：
  - 重复次数大于 1：先写 `n`（十六进制），再写 `p`。
  - 只重复 1 次：只写 `p`。
- 文件开头写 `okti`，第二行写宽和高。

**第三步：解压图片（逆向操作）**

- 打开 `.okti`，检查第一行是不是 `okti`。
- 读第二行得到宽、高，算出应有像素数 `宽 × 高`。
- 逐行读指令：遇到 `n` 记下重复次数，遇到 `p` 按该次数填入颜色。
- 全部解析完后，把解析到的像素个数和 `宽 × 高` 比较，不一致就打印警告，少的补黑、多的裁掉。
- 填进新画布，保存为 `.png`。

### 3. 常见踩坑点

1. **文件头不对**：第一行不是 `okti`（被改过、空文件或损坏）必须报错，不能强行解压。
2. **空行或空指令**：空行转十六进制会崩溃，读取时要跳过空行。
3. **`n` 指令后缺少数字**：单独一行 `n` 没有重复次数时，要给出提示，不能直接 `int('', 16)`。
4. **`p` 指令颜色必须是 6 位十六进制**：`pA1` 或 `p1234567`、以及 `pGGGGGG` 这种非十六进制都要拒绝。
5. **像素总数对不上**：宽高是 `100×100`（10000 个像素）但只解析出 9000 个，说明数据丢失。程序要输出警告，再裁剪或补齐，避免 `putdata` 长度不匹配。

### 4. 具体数据流程

以 2×2 图为例，像素顺序为红、红、绿、蓝：

```
原图像素: (255,0,0), (255,0,0), (0,255,0), (0,0,255)
    ↓ encoder
okti
2 2
n2
pFF0000
p00FF00
p0000FF
    ↓ decoder
还原像素与原图逐点一致
```

## 项目说明文档

### 一、输入-输出示例

以下为一组完整的运行示例（在 `task2` 目录下执行）。

**1. 压缩示例**

- 输入文件：`test/test3.png`（风景 PNG）
- 输出文件：`test/output3.okti`
- 运行命令：

```
python main.py compress test/test3.png test/output3.okti
```

结果：生成 `output3.okti`。

**2. 解压示例**

- 输入文件：`test/output3.okti`
- 输出文件：`test/restored3.png`
- 运行命令：

```
python main.py decompress test/output3.okti test/restored3.png
```

结果：生成 `restored3.png`。与原图逐像素比较差异为 0，属于无损还原。肉眼看风景图也与原图一致。

另外两张样例同样可以无损还原：

```
python main.py compress test/solid_red.png test/output.okti
python main.py decompress test/output.okti test/restored.png

python main.py compress test/test2.png test/output2.okti
python main.py decompress test/output2.okti test/restored2.png
```

### 二、本次压缩的数据缩减量记录

这里比较的是 **原 PNG 字节数** 和 **`.okti` 字节数**（不是还原后的 PNG）。文本 RLE 只在大块同色时更省空间；颜色变化多的图写成 `n`/`p` 文本后往往会膨胀。

| 测试用例 | 原 PNG | 压缩后 .okti | 体积变化 |
| --- | --- | --- | --- |
| `test/solid_red.png`（纯色图，50×50） | 195 字节（约 0.19KB） | 24 字节 | 缩减 87.69% |
| `test/test2.png`（黄黑渐变，100×50） | 402 字节（约 0.39KB） | 1212 字节（约 1.18KB） | 膨胀 201.49% |
| `test/test3.png`（风景图，256×256） | 137181 字节（约 133.97KB） | 499605 字节（约 487.90KB） | 膨胀 264.19% |

纯色图能明显看出 RLE 的好处；渐变和风景图用来说明：这种自定义文本格式的目标是格式简单、可无损还原，不是在所有图片上都优于 PNG。

### 三、容易出错的情形

**1. 文件头缺失或错误**

- **触发场景**：`.okti` 被改过，第一行不是 `okti`，或文件为空。
- **后果**：格式无法识别，继续读会得到乱数据。
- **处理逻辑**：读完第一行立即校验，不符合就抛出 `ValueError("文件头不是 okti")`，终止解压。宽高行缺失或不是两个正整数时，抛出 `ValueError("宽高行无效")`。

**2. `n` 指令后缺少数字**

- **触发场景**：单独一行 `n`，后面没有十六进制重复次数；或出现 `n-1` 这类非正十六进制。
- **后果**：`int('', 16)` 会崩溃，负数次数会把颜色整段丢掉。
- **处理逻辑**：`cmd[1:]` 为空或不是十六进制时抛出 `"缺少重复次数"`；解析结果小于 1 时抛出 `"重复次数必须为正"`。次数大到可能撑爆内存时抛出 `"重复次数过大"`。

**3. 颜色格式不是 6 位十六进制**

- **触发场景**：`pA1`、`p1234567`，或 `pGGGGGG`。
- **后果**：按 6 位切片会错位或 `int(..., 16)` 失败。
- **处理逻辑**：用正则校验必须正好 6 位 `0-9A-Fa-f`，否则抛出 `"颜色格式错误，预期6位十六进制"`。

**4. 空行干扰**

- **触发场景**：文件里被插入空行。
- **后果**：空字符串当指令用，访问 `cmd[0]` 会出错。
- **处理逻辑**：读取时过滤空行：`[line.strip() for line in f.readlines() if line.strip()]`。

**5. 像素总数对不上**

- **触发场景**：宽高是 `100×100`（10000 个像素），解析结果只有 9000 个，或比 10000 更多。
- **后果**：画面缺角、发黑，或多出来的颜色被丢掉。
- **处理逻辑**：解压结束后比较 `len(pixels)` 与 `w * h`。不相等则打印 `警告: 解析像素 {实际} 与宽高乘积 {期望} 不一致`。少了补 `(0, 0, 0)`，多了裁成 `pixels[:w * h]`，再交给 `Image.putdata()`。

### 四、拓展功能：输出运行统计信息

在 `main.py` 里加了运行状态输出。压缩或解压时，终端会打印耗时、输入/输出文件大小；压缩成功时再打印数据缩减量。如果 `.okti` 比原图还大，会改成打印“膨胀百分之多少”，避免出现负数压缩率。参数错误、找不到文件或编解码失败时，进程以状态码 1 退出。

**设计初衷：**

1. **反馈**：不要运行完没有任何输出，让人不知道成没成功、跑了多久。
2. **衡量算法**：RLE 效果取决于图片重复度。看缩减量/膨胀量，能直接对比纯色图和风景图。
3. **性能**：几百 KB 的图加上耗时，能看出像素循环是否过慢。
4. **体验**：失败时给出原因并返回非 0，方便脚本判断。
